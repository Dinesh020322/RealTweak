# RealTweak AR (Unity)

Unity 6000.0.32f1 · AR Foundation 6.2 (ARCore 6.2 / ARKit 6.2) · URP 17 · Input System · Firebase Unity SDK 12.10 (App, Auth, Firestore, Storage).

## Project layout

```
Assets/RealTweak/
  Scripts/Core/        Pure C# (no UnityEngine) — unit-tested with dotnet in CoreTests~
    RoomModel.cs         Room document model (web coordinates)
    RoomCodec.cs         Firestore dict ⇄ Room, room codes, three-way merge
    RoomOps.cs           Corner move/insert/remove, wall length, ceiling, square-up (same rules as the website)
    RoomReconstructor.cs SmartScan: samples → outline, ceiling, doors, windows, furniture
    Alignment.cs         Two-corner alignment, Smart-align registration (ICP), scan → room document
  Scripts/Runtime/     Unity components
    AppController.cs     Screens and flow (home, join, scan, review, align, live room)
    ScanCapture.cs       Samples from depth raycasts, feature points, planes, LiDAR mesh; live preview
    RoomView.cs          AR rendering of walls/openings/floor + furniture reconciled by id
    FurnitureFactory.cs  Catalog parts → GameObjects (same parts as the website)
    CloudService.cs      Anonymous auth, create with code retry, merge-on-save, listener, presence
    ARInteraction.cs     Tap/drag/twist gestures for furniture and room placement
    PlanEditor.cs        Touch plan editor used after scanning and in the live room
    IconRenderer.cs      Catalog thumbnails rendered on device
    UIKit.cs, MeshKit.cs, Catalog.cs
  Editor/RealTweakSetup.cs  Builds the scene, materials, prefabs, player settings; Android build
  Resources/RealTweakCatalog.json  Generated by the website (npm run catalog) — do not edit
Assets/Scenes/RealTweakAR.unity    Generated by RealTweak ▸ Build App Scene
CoreTests~/                         dotnet test runner for Scripts/Core (ignored by Unity)
Legacy~/                            The previous prototype scripts and scene (ignored by Unity)
```

The UI is built in code (`UIKit`), so nothing has to be wired in the Inspector. The scene builder is idempotent: re-run **RealTweak ▸ Build App Scene** after changing it.

## Build

1. Open the project in Unity 6000.0.32f1 with Android (and/or iOS) Build Support.
2. **RealTweak ▸ Build App Scene** (creates `Assets/Scenes/RealTweakAR.unity` and sets player settings: portrait, IL2CPP, ARM64, GLES3, bundle id `com.FourFriendsInteractive.RealTweakAR`).
3. Android: **RealTweak ▸ Build Android APK** → `Builds/RealTweakAR.apk`, or File ▸ Build Profiles. Command line:

   ```bash
   Unity -batchmode -nographics -buildTarget Android -projectPath RealTweak_AR -executeMethod RealTweak.EditorTools.RealTweakSetup.BuildAndroid -logFile build.log
   ```
4. iOS: switch to iOS, build, open the Xcode project, set signing. `GoogleService-Info.plist` is already in `Assets/`; the bundle id must match the iOS app registered in Firebase (register it if you haven't).

ARCore is set to **Required** (the app needs AR) and **Depth to Optional**, so phones without the Depth API still install and scan with feature points/planes.

## Firebase

`Assets/google-services.json` (Android) belongs to Firebase project `realtweak`, package `com.FourFriendsInteractive.RealTweakAR`. Before release:

* Authentication → enable **Anonymous** sign-in.
* Deploy the rules from `RealTweak_Website` (`firestore.rules`, `storage.rules`). Storage rules read Firestore to check the room exists — accept the cross-service permission prompt on first deploy.
* Optionally enable App Check (Play Integrity / App Attest) and enforce after testing.

## Unit tests for the pure core

```bash
cd RealTweak_AR/CoreTests~
dotnet run
```

Runs codec, merge, room-op, alignment and SmartScan checks (30 randomized synthetic rooms with noise, missing samples, a door, a window and furniture). Set `RT_DEBUG=1` to print detections.

## Tuning SmartScan

Thresholds live at the top of the relevant methods in `RoomReconstructor.cs` (wall height ≥ 1.25 m, 5 cm grid, door 0.65–1.35 m, window band 1.0–1.8 m, furniture classification table in `Classify`). Real-room accuracy depends on lighting, texture and how slowly the user walks; corner mode and the review editor are the fallbacks for difficult rooms.

## Testing on a phone (e.g. Samsung Galaxy S20 FE)

The S20 FE is ARCore-certified and supports the ARCore Depth API, so it uses the dense depth scanning mode.

1. On the phone: Settings ▸ About phone ▸ Software information ▸ tap *Build number* 7× → Developer options ▸ enable **USB debugging**. Make sure *Google Play Services for AR* is installed/updated from the Play Store.
2. Connect by USB and install the APK built by **RealTweak ▸ Build Android APK**:

   ```bash
   "D:/Unity/UnityEditor/6000.0.32f1/Editor/Data/PlaybackEngines/AndroidPlayer/SDK/platform-tools/adb.exe" install -r Builds/RealTweakAR.apk
   ```
   (or File ▸ Build Profiles ▸ Android ▸ *Build And Run* with the phone connected).
3. Before testing cloud features: enable Anonymous sign-in and deploy the rules from `RealTweak_Website` (see its README). Without them, saving shows "Access denied".
4. Logs: `adb logcat -s Unity` or Unity's Android Logcat window (package already installed).
